TOOT AND SCUTE — Master Systems Specification (v1)Status: Design spec, mid-implementation. The Cloudflare Worker $\longrightarrow$ Durable Object handshake and the two-way WebSocket connection are confirmed working. Everything downstream of that connection—the message protocol, the content pipeline, and the playout client—is design-stage.
Scope: End-to-end architecture for an unattended, continuously-running streaming channel: chosisme-formalist scripted scenes rendered locally via Remotion, a Cloudflare Worker/Durable Object scheduling backend, a namespaced JSON control protocol, and a browser-based playout client (OBS + PixiJS + React) that turns it all into a live broadcast.
Revision Note: First consolidated master specification. Format mirrors the foundation-first structure: Part I fixes what is confirmed vs. open forks; subsequent parts build outward only once the underlying layer is established.
--------------------------------------------------------------------------------
PART I — THE OUTERMOST LAYER (BROADCAST & AUTH)1. What Is Confirmed vs. What Is Still a ForkConfirmed & Operational: The Cloudflare Worker validates the incoming connection and hands it to a Durable Object (DO), which owns a live, two-way WebSocket.Open Architectural Decisions: OBS ingestion path (playout vs. live-render), authentication scope (operator vs. viewer), and video texture alpha composition.2. OBS Ingestion: Live-Render vs. PlayoutLive-Render Path: OBS Browser Source (embedded CEF/Chromium) points at a local webpage hosting @remotion/player. Scene props arrive over WebSockets; composition renders live in real time. Provides reactive dynamic control at the expense of rendering fragility (dropped frames, CEF performance limits).Playout Path (Recommended Standard): Scenes are pre-rendered to finished .mp4 files via the local batch pipeline (Part III). OBS's Media Source or VLC Source plays a queue of finished files. The WebSocket carries scheduling and overlay control—never pixels.3. Authentication Layer (Clerk)Scope Definition: Operator/machine authentication. The local broadcast machine authenticates its session via Clerk to prove to the Worker that it is the sanctioned broadcast client before channel state is transmitted. No audience-facing paywall or subscriber system is implied.4. Cloudflare Worker + Durable ObjectThe Stateless Handshake: A bare Worker cannot hold WebSockets open for long broadcasts. The Worker intercepts the HTTP upgrade request, validates the Clerk token, and hands the socket to a Durable Object.WebSocket Hibernation API: The DO utilizes the WebSocket Hibernation API, enabling the edge proxy to maintain TCP connections while evicting the DO’s in-memory JavaScript between messages, ensuring sustainability for 24/7 channels.Scheduling Authority: The DO serves as the single source of truth for channel programming and state.Load-Bearing Rule: Hibernation evicts in-memory instance fields. Any state needed to answer resync queries must be written through to ctx.storage on every change and read back dynamically.

PART II — THE CONTROL PROTOCOL (WEBSOCKET)5. Message EnvelopeEvery message separates a thin, fixed envelope (routing/replay concerns) from a type-specific payload (domain data):interface Envelope<T extends string, P> {
  type: T;            // Dot-namespaced, e.g. "scene.play"
  seq: number;        // Monotonic per-connection (gap detection for resync)
  v: 1;               // Protocol version
  serverTime: number; // Epoch ms (clock-offset math for seeking)
  payload: P;
}
6. Dot-Namespacing & Routingtype strings are dot-prefixed by domain (scene.play, overlay.show, audio.setBed, pixi.trigger, system.ping). The prefix serves as the routing key: client dispatchers route by type.split(".")[0] to the appropriate subsystem reducer before per-type logic executes.7. Message TaxonomyState-Replace (scene.play, overlay.show, audio.setBed): Idempotent. Replaying during resync simply resets state. Default shape.One-Shot Triggers (scene.skip, pixi.trigger): Non-idempotent. Carries an actionId (UUID) so clients can deduplicate received actions.Client-Reported Events (scene.ended, scene.error): Client $\longrightarrow$ DO telemetry feeding the server's state machine.8. Schema Validation at the BoundaryValidated bidirectionally via Zod using safeParse:const SceneRef = z.string().regex(/^SC-\d{2,4}$/);

const PlaySceneMsg = z.object({
  type: z.literal("scene.play"),
  sceneId: SceneRef,
  sceneStartTime: z.number(),
  audioBedVersion: z.string(),
});

const ServerMessage = z.discriminatedUnion("type", [
  PlaySceneMsg, ShowOverlayMsg, ResyncSnapshotMsg,
  z.object({ type: z.literal("system.ping"), serverTime: z.number() }),
]);
Validation Rules: Constrain values semantically (regex on scene IDs, bounded numeric offsets); distinguish unknown types from invalid payloads; fail open per-message; route errors to out-of-band webhooks.9. Reconnect & Resync MechanicsDO-Side: Active state persisted via ctx.storage to survive hibernation eviction.Client-Side: Exponential backoff with jitter; heartbeat-driven staleness watch independent of close events; mandatory system.resyncRequest on connect; custom close codes (4000–4999) distinguishing transient drops from expired Clerk sessions. Application-level heartbeats (system.ping) substitute for unavailable browser ping frames.Clock Offset & Sequences: serverTime allows client video seeking: $$\text{elapsedMs} = (\text{Date.now()} + \text{clockOffsetMs}) - \text{sceneStartTime}$$ Gaps in monotonic seq trigger automatic resync requests.10. PART III — CONTENT GENERATION PIPELINE (CHOSISME / REMOTION)11. The Script Markdown as Source of TruthHuman readability is mandatory. No parallel JSON is maintained. Because the chosisme specification enforces locked output geometry (fixed headings, Kinetic Curve tables, bold TRIAD N, italicized Hold X frames), a unified remark AST parser extracts durations, hold frames, and curve metrics directly from .md files.12. Markdown-to-Composition MappingBeats 1–6: Map to <Sequence> wrappers; duration set from measured Narrator V.O. length via getAudioDurationInSeconds.Kinetic Curve Table: Drives interpolate() on frame indices for camera zoom, shake, and exposure.Triad A/B/C: Nested sequences; Phase B (Action) hold frames anchor Foley events and stingers.Directorial Rules: Frame-precise hard cuts between beats (banning emotional transitions); programmatic Blackout Test (renderMode="blackout") automating silhouette QA.13. Local Batch Rendering & ConcurrencyLocal rendering via @remotion/renderer (renderMedia). No cloud Lambda.Concurrency is non-monotonic; benchmarked via npx remotion benchmark.Sequential rendering with optimal internal concurrency (Pattern A) is the standard for overnight batches to avoid memory oversubscription.

PART IV — THE AUDIO SYSTEM14. Two Layers: Geometric Bed & Parsed FoleyAmbient / Textural Bed: Continuous, driven by the Kinetic Curve table (Level $\rightarrow$ layer density/gain; Phase $\rightarrow$ texture lookup). Loops tagged by measurable acoustics (spectralCentroidHz, intensityBand), never mood.Foley: Parsed sentence-by-sentence from script Sound production notes, matched by shared nouns to Triads, and snapped to Triad B hold frames. Lexical mapping dictionaries unify visual entity descriptions with sibling audio sample keys.Deliberate Silence: Encoded as explicit ducking events (duckAmbientDb: -24).Decoupled Continuity: Audio bed persists across hard visual Beat cuts with linear crossfades.15. The Audio Bed Manifestinterface SceneAudioBed {
  sceneId: string;
  ambientLayers: { loopId: string; fromFrame: number; toFrame: number; gainDb: number | { atFrame: number; gainDb: number }[] }[];
  foleyEvents: { cueText: string; triadId: number; atFrame: number; sampleId: string; gainDb: number }[];
  silences: { fromFrame: number; toFrame: number; duckAmbientDb: number }[];
  duckUnderVO: { fromFrame: number; toFrame: number; duckDb: number }[];
}
16. Deterministic SeedingRemotion forbids native Math.random(). Seeding uses random(seed) backed by Mulberry32:Compound seed key: ${sceneId}:${triadId}:${dictionaryKey} ensures stability against unrelated edits.Samples resolved once at generation time and baked into the manifest.Cross-scene variety enforced via deterministic shuffled decks: sceneOrdinal % pool.length.

PART V — THE PLAYOUT CLIENT17. Single Store, Two RenderersA single client store (Zustand/event emitter) receives validated WebSocket packets. PixiJS (generative canvas/video) syncs imperatively via useEffect; React renders structured DOM overlays off derived store state, preventing dual-parser drift.18. Video CompositingOpaque Video (H.264 / H.265): Full-frame playback during scenes; Pixi active during idle/transitions.Alpha Video (ProRes 4444 / WebM VP9 with Alpha): Required if Pixi generative graphics must composite underneath transparent regions of the Remotion video.19. Idle FallbackOn connection staleness or overlay.hideAll, the client activates a procedural Pixi idle state, preventing frozen video frames on stream.

PART VI — OPERATIONAL CONCERNS20. CEF Degradation & obs-websocketOBS Browser Sources (CEF) accumulate memory over long unattended runs. An external obs-websocket connection (port 4455) executes scheduled cache refreshes (Refresh cache of current page), separating content delivery from operational broadcast control.21. Logging & ObservabilityMalformed packet rejections and playback errors route out-of-band (e.g., Discord/Slack webhooks) to ensure unattended failures are immediately visible.
