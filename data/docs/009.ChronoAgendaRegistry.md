## 1. Architectural Purpose Across the Fleet

Without an explicit scheduled story agenda, unattended tick simulations rely purely on stochastic drama thresholds or filler drought cooldowns. A sudden random hallway argument right before an authored midnight ball or tribunal drains actors' emotional bandwidth, burns scene budget, or triggers colliding scene locks when the canonical plot appointment arrives.

`ChronoAgendaRegistry` installs deterministic, Gregorian calendar-aware story appointments into `chronology.scheduled_beats` so all four fleet repositories coordinate around authored tentpole deadlines:

```text
000.goblin-lore (299.lore)
  Author scheduled_beats in chronology -> validate Gregorian dates, reserveCooldownTicks,
  overlaps, locationId/participantIds foreign keys -> emit world/chrono-agenda.md ->
  seal deterministic JCS bible-state.json -> inspect [PUBLISH:AGENDA] parity
        |
        v
000.goblin-spatial (301.spatial)
  Project scheduled appointment startTimeHm into diurnal phases (DAWN..NIGHT) ->
  verify venue reachability, lighting telemetry, acoustic exposure ->
  export signed agenda-spatial-proofs.json receipt to Engine
        |
        v
000.series-sower-engine (300.engine)
  Evaluate pure Gregorian epoch crossing (prevTimestampSec, currentTimestampSec] ->
  suppress generic drought fillers inside reserveCooldownTicks pre-deadline window ->
  guarantee deterministic ignition (one-shot or recurringDaily) ->
  emit Agenda-Beat-Id / Scheduled-Time / Reserve-Held-Ticks Fountain headers + index.json agendaSummary
        |
        v
000.series-sower-conductor (400.conductor)
  Parse Fountain Agenda headers into scene AST -> reconcile required appointments vs
  captured scenes (MATCH / MISS) -> generate dramatic tentpole pause cues ->
  seal agendaCompliance summary inside JCS stack_receipt.json + episode_manifest.json
```

## 2. Core Data Contract

Each scheduled story appointment inside `chronology.scheduled_beats` carries these fields:

| Field | Type / Constraint | Purpose |
| :--- | :--- | :--- |
| `beat_id` | Non-empty identifier string | Canonical key sorted deterministically and sealed across manifests. |
| `title` | Human-readable string | Scene beat headline surfaced in TUI menus, Fountain metadata, and Conductor audits. |
| `isoDate` | `YYYY-MM-DD` Gregorian date | Calendar target date; strictly checked for leap years (e.g. rejects `2025-02-29`) and `>= simulation startDate` (`AGENDA_IN_THE_PAST`). |
| `startTimeHm` | `HH:MM` 24-hour clock | Clock target on `isoDate` (rejects `24:60` or malformed strings). |
| `beatCategory` | Enum (`PLOT_TENTPOLE`, `RITUAL`, `MEETING`, `CONFRONTATION`, `REVELATION`, etc.) | Classifies tentpole framing and Conductor tentpole pause choreography. |
| `reserveCooldownTicks` | Integer `[0, 1000]` | Pre-deadline quiet window (in simulation ticks) where trivial drought fillers are suppressed so narrative tension holds cleanly for the appointment. |
| `priorityBps` | Integer `[0, 10000]` | Basis-points tie-breaker / precedence weight across nearby appointments. |
| `locationId` | Optional entity ID | Target room verified against Spatial room registry during Gate 0 compilation and Spatial pre-flight proofs. |
| `participantIds` | Optional array of character IDs | Required cast verified against Lore actor registry (`[AGENDA_UNKNOWN_ENTITY_REF]` on unknown IDs). |
| `recurringDaily` | Optional boolean | Enables 24-hour periodic firing at `startTimeHm` across multi-day simulation rollovers without losing exact second alignment. |
| `toleranceTicks` | Optional non-negative integer | Catch-up grace window in ticks when coarse tick durations step past `startTimeHm`. |

## 3. Date-Time Engineering Highlights

1. **Coarse-Tick Timestamp Crossing:** Simulations advance by discrete integer ticks (e.g., 15 minutes or 60 minutes per tick). Pure epoch evaluation checks the half-open interval `(prevTimestampSec, currentTimestampSec]` against the appointment's Gregorian epoch second plus optional `toleranceTicks` instead of brittle exact-second equality, so appointments never skip silently across coarse ticks.
2. **Midnight Rollover with Daily Recurrence:** When `recurringDaily` is enabled, multi-day rollovers (`23:45` -> `00:15` next day) project onto every crossed Gregorian day boundary cleanly without re-firing twice on the same virtual calendar day.
3. **Past-Date Rejection (`AGENDA_IN_THE_PAST`):** Chronology validation compares every scheduled beat timestamp directly against the simulation's active `startDate` + `startTimeHm`, catching backdated deadlines at compile time rather than stalling in Engine runs.
4. **Diurnal Lighting Projection:** Spatial translates each appointment's `startTimeHm` into diurnal visibility/lighting bands so nocturnal infiltration beats or dawn tribunal scenes fail fast if scheduled inside physically incompatible room constraints.

## 4. Step-by-Step Blessed TUI Operations Guide

Follow Steps A -> D in order to author, certify, simulate, and audit scheduled story appointments across all four Blessed TUI cockpits.

> **7-Bit Pure ASCII Telemetry Standard:** Once Blessed initializes, never expect stdout debug text; monitor the green right-hand `cns00` console pane (`COLOR.GREEN`) for `>> [...]` confirmations and `:: [...]` failure alerts.

### Step A: Authoring, Validation, Compilation in `000.goblin-lore`

1. Launch the Lore cockpit from `D:\trellis\000.goblin-lore`:
   ```powershell
   cd D:\trellis\000.goblin-lore
   npm run tui
   ```
2. In `LORE MENU` (left control pane), press `[S] SWITCH ACTIVE SERIES` to focus your target series (or `[G] UNIVERSAL SERIES GENESIS WIZARD` to bootstrap a new series).
3. Open Chronology configuration:
   - Select `[T] SIMULATION CHRONOLOGY CLOCK` from `LORE MENU`.
   - Select `[6] SCHEDULED STORY APPOINTMENTS (AGENDA)` (dispatches `MANAGE_CHRONO_AGENDA`).
4. Inside the Scheduled Story Appointments submenu:
   - Press `[1] LIST SCHEDULED APPOINTMENTS` to review currently registered beats in `cns00`.
   - Press `[2] ADD SCHEDULED STORY BEAT` and supply `beat_id`, `title`, `isoDate`, `startTimeHm`, `beatCategory`, `reserveCooldownTicks`, `priorityBps`, plus optional `locationId`, `participantIds`, `recurringDaily`, and `toleranceTicks`.
   - Press `[3] REMOVE SCHEDULED BEAT BY ID` if you need to prune or replace a beat.
   - Press `[4] PREVIEW RESERVE COUNTDOWN TIMELINE` to inspect `>> [AGENDA:BEAT] ...` telemetry showing exact tick indices, Gregorian timestamps, reserve suppression start ticks, and overlap checks.
   - Press `[<] BACK TO CHRONOLOGY MENU`, then return to `LORE MENU`.
5. Run Gate 0 compilation:
   - Select `[C] COMPILE CANON & GATE 0 GAUNTLET`.
   - Confirm `cns00` passes foreign-key validation (zero `[AGENDA_UNKNOWN_ENTITY_REF]`), rejects no backdated beats (zero `AGENDA_IN_THE_PAST`), writes Byte-0 LF-only `world/chrono-agenda.md`, and seals sorted `chronology.scheduled_beats` into `bible-state.json`.
6. Publish to the fleet:
   - Select `[P] PUBLISH SEALED CANON TO SIMULATION FLEET`.
   - Verify the telemetry line in `cns00`:
     `>> [PUBLISH:AGENDA] count=<n> first=<isoDate> <HH:MM> (<category>)`.

## 6. High-Value Missing Elements Analysis

The baseline `ChronoAgendaRegistry` pipeline guarantees temporal scheduling, pre-deadline drought suppression, spatial lighting pre-flight validation, and downstream Conductor sealing. Six structural capabilities remain outside v1 scope and represent high-leverage improvements for realistic multi-episode production:

1. **Pre-Appointment Participant Travel Convergence Lockout:**
   - *Current Gap:* `reserveCooldownTicks` suppresses random drought filler scenes, yet actors listed in `participantIds` remain free to drift across distant rooms until the exact deadline tick triggers.
   - *Why It Matters:* Without transit lead-time reservation, characters appear to teleport into `locationId` on `startTimeHm` rather than exiting neighboring scenes naturally before the meeting opens.
2. **Conditional Prerequisite Chains with Fallback Beats:**
   - *Current Gap:* Appointments evaluate calendar time and entity references unconditionally; an appointment cannot require that an earlier story beat resolved or substitute an alternate beat if the prerequisite failed.
   - *Why It Matters:* Narrative causality breaks if a reconciliation dinner fires identically whether two rivals made peace or clashed earlier in the afternoon.
3. **Deterministic Conflict Rescheduling / Slippage Escalation:**
   - *Current Gap:* `evaluateChronoAgendaWindow` fires strictly within the timestamp crossing / `toleranceTicks` window, or Conductor flags `[AGENDA_AUDIT:MISS]`; v1 lacks automated deterministic deferral rules when a required participant is incapacitated or a venue is blocked dynamically mid-run.
   - *Why It Matters:* Long autonomous runs benefit from rule-driven postponement (`deferredToIsoDate`, `escalationBeatId`) rather than silently dropping a beat or halting mid-series.
4. **In-Scene Ticking-Clock Fountain Foreshadowing:**
   - *Current Gap:* Engine suppresses filler inside `reserveCooldownTicks`, but adjacent scenes occurring right before an appointment lack automatic countdown cue injection (`Reserve-Remaining-Ticks` / impending deadline subtext).
   - *Why It Matters:* Screenwriters and LLM scene expanders gain dramatic urgency when characters organically acknowledge an approaching deadline two ticks prior.
5. **Non-Daily Calendar Recurrence Grammar (Weekdays, Moon Phases, Blackouts):**
   - *Current Gap:* `recurringDaily` supports either one-shot (`isoDate`) or every-day repetition.
   - *Why It Matters:* Court sessions every Friday, weekly market days, solstice festivals, or lunar rituals require weekday masks, interval periods, and holiday blackout exceptions.
6. **Multi-Beat Simultaneous Ensemble Staging:**
   - *Current Gap:* Overlapping appointments at the exact same timestamp compete via `priorityBps` sorting rather than grouping intentionally into split-screen / parallel-room ensemble acts.
   - *Why It Matters:* Season finales often demand synchronized parallel beats at `23:59` across separate venues (`throne-room` vs `catacombs`) linked under one shared act header.

## 7. Suggested Next Features

Recommended implementation sequence for follow-on gravity directives after all `ChronoAgendaRegistry` phases pass:

1. **`ChronoTransitLockRegistry` (Engine + Spatial):** Compute topological shortest-path hop ticks from each `participantId`'s current room to `locationId`, locking free-roam wandering `N = reserveCooldownTicks - pathHops` ticks prior so actors physically walk into frame ahead of `startTimeHm`.
2. **`AgendaPreconditionRouter` (Lore + Engine):** Add optional `requiresBeatIds`, `forbiddenStateFlags`, and `fallbackBeatId` fields to `ScheduledBeatSchema` with static cycle detection in Gate 0 and deterministic fallback routing in `17.tick.unit`.
3. **`CalendarRecurrenceRuleset` (Lore + Engine):** Extend `recurringDaily` with `recurrencePattern` (`ONCE`, `DAILY`, `WEEKLY_MASK`, `INTERVAL_DAYS`, `BLACKOUT_DATES`) while preserving pure Gregorian math without runtime system-clock reads.
4. **`ForeshadowCueInjector` (Engine + Conductor):** Emit `Upcoming-Deadline-Beat-Id` and `Ticks-Until-Appointment` headers into scenes generated inside `[T - reserveCooldownTicks, T)` so Conductor downstream renderers emphasize mounting tension.
5. **`MultiRoomTentpoleSync` (Spatial + Engine + Conductor):** Allow an explicit `ensembleGroupId` so intentionally parallel beats at the same `isoDate` + `startTimeHm` share cross-cut sequence numbers in `episode_manifest.json` instead of triggering collision alerts.
