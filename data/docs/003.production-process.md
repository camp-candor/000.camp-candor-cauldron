### Step-by-Step Production Process

#### Step 1: Script Ingress and Invariant Verification

1. **Draft Ingress:** The raw `.fountain` screenplay enters the staging pipeline within `worker-sower-engine/drafts/`.


2. **Pass 0 Byte Sanitization:** The file undergoes pre-flight byte inspection to verify that byte 0 begins cleanly with frontmatter markers, that character encoding strictly uses clean 7-bit ASCII without multi-byte Unicode artifacts, and that file paths conform to sandboxed directory boundaries.


3. **Compile-Time Invariant Gauntlet:** Before converting to an AST, the script’s action lines and dialogue are evaluated against `001.goblin-lore` canonical state:


* *Somatic Action Verification:* Character physical actions are checked against active somatic capability profiles (e.g., verifying an amputee or bedridden entity never attempts an impossible motor movement).


* *Epistemic Horizon Audit:* Spoken dialogue is checked against the character’s known belief boundaries to guarantee no narrative secrets or unearned third-rail knowledge are uttered.





#### Step 2: Deterministic AST Compilation and Parity Gate

1. **Grammar-Constrained Extraction ($T = 0.0$):** `worker-sower-engine` executes an automated inference pass at zero temperature constrained by a deterministic Context-Free Grammar (GBNF). The screenplay prose is converted into a strongly typed machine contract (`dialogue_ast.json`) containing discrete shot nodes, speaker IDs, verbatim spoken dialogue text, parentheticals, somatic parameters, and Foley action cues.


2. **Verbatim Parity Assertion:** An automated gate normalizes whitespace and punctuation, asserting absolute character-for-character equality between the spoken lines in the `.fountain` file and the dialogue strings in `dialogue_ast.json`. Any divergence halts compilation instantly at zero compute spend ($T_0 = \$0.00$) before downstream audio processes are allocated.



#### Step 3: Neural Voice Synthesis, Ephemeral Subprocess Invocation, and Blessed Cockpit Telemetry

1. **Hardware Preparation & Turn-Based VRAM Eviction:** Before vocal synthesis begins, `series-sower-conductor` sends a synchronous HTTP POST request to the local ComfyUI memory release endpoint (`POST [http://127.0.0.1:8188/free](http://127.0.0.1:8188/free)`), evicting upstream drafting LLMs and preliminary diffusion checkpoints from memory in approximately 300 ms to establish unfragmented host headroom.


2. **The Zero-VRAM Invariant:** `microservice-audio` and its child processes execute with an invariant hardware allocation of exactly 0 MB dedicated GPU VRAM. The execution environment sets an empty CUDA device mask (`CUDA_VISIBLE_DEVICES=""`), binding all neural vocoders, latent calculations, and DSP filtering exclusively to multi-core CPU threads and system RAM.


3. **Biological Trauma Vector Compilation & Phonation Feasibility Gate:**
* In `14.conditioning.unit`, the character's biological condition records are retrieved from the canonical state ledger (`pilot.db` or Cloudflare D1), measuring trauma and fatigue in integer basis points ($0 \dots 10{,}000\text{ bps}$).


* An automated pre-flight gate checks whether vocal delivery is physiologically possible. If a character's state logs airway blockage, transected vocal cords, or muteness, compilation terminates immediately at $T_0 = \$0.00$ with a fatal `VOCAL_DELIVERY_BREACH` before any synthesis worker is spawned.


* In `12.acoustic.unit`, somatic basis points are translated algebraically into dynamic DSP modifiers: fundamental frequency ($F_0$) is shifted in semitones based on pain and threat; pharyngeal geometry is scaled into a formant warping factor ($0.5 \dots 2.0$); pulmonary trauma expands breathiness pause multipliers (up to $3.5\times$) to mechanically fragment clauses; and physical fatigue is mapped to subharmonic vocal fry density ($0.0 \dots 1.0$).




4. **Offline Dialect Expansion & Phonetic Firewall:** Clean, grammatical English from the AST passes through `voices/<series_id>/lexicon.json` offline on Rig 1. Sequential PCRE regex expressions expand colloquial contractions, proper nouns are swapped with phonetic pronunciations, and delivery is validated against character-specific banned cadence tables.


5. **Programmatic Conductor Manipulation of the Blessed Terminal Cockpit:**
* *Direct In-Process Orchestration:* Because `series-sower-conductor` and `microservice-audio` coexist on Rig 1, the conductor drives `microservice-audio` without network sockets or long-lived HTTP daemons.


* *Cartesian 12x12 Screen Partitioning:* The UI inside `apps/995.library` adheres to an immutable 12-column by 12-row Cartesian grid matrix (`81.grid.unit`):


* **Left Control Quadrant:** Columns 0 through 4, Rows 4 through 12 (`{ x: 0, y: 4, w: 4, h: 8 }`), governed by `98.menu.unit` and rendered by `85.choice.unit`.


* **Right Telemetry Quadrant:** Columns 4 through 12, Rows 0 through 12 (`{ x: 4, y: 0, w: 8, h: 12 }`), housing the green-bordered switchboard console (`83.console.unit` / `cns00`).




* *Shared Pivot Bus Action Injection:* The conductor resolves `global.MICROSERVICEAUDIO` and `global.PIVOTS['microserviceaudio']`, dispatching strongly typed action payloads via the `hunt` method directly into `microservice-audio`'s event bus without requiring manual operator keystrokes.


* *Choice Interception & Synchronized Highlighting:* The conductor intercepts and resolves choice promises (`slv` / `rootSlv`) on `98.menu.unit`, advancing the selection cursor programmatically and updating menu labels with active execution badges.


* *Status HUD & Border Theming:* Via `80.terminal.unit`, the conductor shifts terminal border colors and updates status banners (displaying active series slug, Merkle root, and synthesis mode) to alert operators that the cockpit is locked in synthesis.


* *7-Bit ASCII Telemetry Streaming to `cns00`:* The conductor streams real-time receipts into `cns00`:


* *Initialization Headers:* Emits banners notifying operators that the master lifecycle has claimed the flight deck.


* *Process Spawning Logs:* Streams the target engine name, character style profile, and assigned process ID.






6. **Ephemeral Subprocess Spawning (`10.generate.unit`):**
* `10.generate.unit` serializes dialogue text, engine flags, reference audio paths, and somatic DSP modifiers into a command-line argument vector.


* Node.js invokes the target external Python runner (`python synthesize.py`) using native system primitives (`child_process.execFile` or `child_process.spawn`) under CPU core constraints.


* The Python worker runs as an isolated, one-shot process that exits with code 0 upon buffer flush, returning 100% of memory to the OS and eliminating background daemon leaks.




7. **Atomic Staging, Non-Blocking Polling, and Inode Stabilization:**
* The Python script writes raw 48 kHz linear PCM audio to an ephemeral sandbox file (`.tmp`, such as `ep01_sh01.wav.tmp`), never directly to production paths.


* `10.generate.unit` runs an asynchronous polling loop ticking every 150 to 250 milliseconds across the libuv event loop, emitting concise heartbeat receipts (check attempts, byte counts) to `cns00` without freezing curses UI threads.


* The buffer is certified stabilized only when byte size remains identical across consecutive ticks and the child process exits cleanly. A 30-second circuit breaker aborts and unlinks stalled files.




8. **The Signal Conformance Gauntlet:**
* *Zero-Byte Poison Buffer Sentinel:* `06.transcription.unit` rejects any buffer under 1,024 bytes or lacking valid RIFF/WAVE headers.


* *Speech Alignment Parity Gate:* An automated transcription pass checks character-for-character parity against the AST `dialogue_text`, trapping dropped words or hallucinations.


* *Acoustic Hygiene Filtering:* High-pass 4th-order Butterworth filtering strips sub-bass rumble below 90 Hz, and dynamic optical de-essing attenuates 6 kHz to 8 kHz sibilance.


* *EBU R128 Loudness Normalization (`01.loudness.unit`):* Normalizes integrated loudness to -16.0 LUFS ($\pm 1.0\text{ LUFS}$) for web or -24.0 LUFS for broadcast.


* *True-Peak Clamping (`02.peaks.unit`):* Digital brickwall limiters clamp peaks strictly to $\le -1.0\text{ dBTP}$.


* *Noise Floor Certification:* Verifies that unvoiced intervals maintain background noise strictly below -60.0 dBFS.




9. **Atomic POSIX Promotion & Clean Menu Release (`97.collect.unit`):**
* `10.generate.unit` triggers `fs.renameSync`, promoting `.tmp` to `.wav` atomically at the kernel level.


* `97.collect.unit` calculates the SHA-256 hash, logs duration, indexes the stem into the collection manifest, and streams the verified LUFS, True-Peak, and calculated frame budget receipts directly to `cns00`.


* `series-sower-conductor` resolves the menu promise, cleanly returning the Blessed cockpit back to its root idle state without memory leaks, hung timers, or unhandled curses exceptions.




10. **Per-Line Isolated Retry Harness:** Single-line synthesis failures are caught by an isolated 3-attempt exponential backoff retry loop ($100\text{ ms} \times 2^{\text{attempt}-1}$), logging structured warnings to `cns00` without invalidating previously stabilized stems.



#### Step 4: Physical Time Measurement and Master Clock Quantization

1. **Temporal Probing via Child Processes:** `series-sower-conductor` spawns an asynchronous POSIX child process executing `ffprobe` against each newly committed `.wav` stem header to measure the continuous waveform duration down to fractional milliseconds ($D_{\text{ms}}$).


2. **Discrete 24 fps Timeline Quantization:** Continuous milliseconds are converted into discrete 24.0 fps integer frames using non-negotiable ceiling arithmetic:



$$\text{target\_frames} = \left\lceil \left(\frac{D_{\text{ms}}}{1000}\right) \times 24 \right\rceil$$





3. **Anti-Drift Timeline Anchoring:** Sequence starting frames accumulate discrete shot frame budgets from origin ($\text{fromFrame}_k = \sum_{i=1}^{k-1} \text{total\_shot\_frames}_i$), eliminating fractional rounding drift.


4. **Exposure Sheet Compilation:** Absolute frame start positions, active speech windows, pre-roll reaction cushions (12 to 24 frames), post-roll holds, and sidechain ducking anchor coordinates are serialized into `exposure_sheet.json`. Progress and lock receipts are streamed live to console pane `cns00`.



#### Step 5: Dual-Output Foley Extraction and Deterministic Seeding

1. **Lexical Extraction:** Action sentences in the AST are scanned for physical interaction nouns and matched against `foley/registry.json` in `goblin-assets-audio` to isolate sound effect categories.


2. **Temporal Snapping:** Transient Foley hits are aligned to explicit frame offsets, snapping either into authored pre-roll reaction windows or onto physical hold-frames.


3. **Deterministic PRNG Seeding:** Specific audio sample variations are resolved by seeding a Mulberry32 pseudorandom number generator using a 32-bit MurmurHash3 string constructed from the scene ID, shot ID, and sample key.


4. **Anti-Clustering Salt:** If the pseudorandom generator selects the identical audio take used in the immediately preceding shot, an anti-clustering retry salt is appended to the hash to force a re-roll and ensure acoustic variation.



#### Step 6: Ambient Bed Selection and Dynamic Sidechain Curves

1. **Continuous Bed Staging:** Sustained atmospheric soundscapes and environmental drone loops matching the scene's spatial metadata are retrieved from `goblin-assets-audio/music/ambient/`.


2. **Decoupled Acoustic Continuity:** Ambient beds are structured to span visual cut boundaries continuously, maintaining consistent spatial immersion across shots.


3. **Dynamic Sidechain Ducking Curves:** The conductor calculates dynamic volume automation: ambient beds maintain baseline unity gain during pauses, but dynamically dip by -14 dB during active dialogue windows via a 6-frame quadratic attack and recover via a 12-frame quadratic release. Inter-dialogue gain anti-pumping logic clamps volume flat during pauses shorter than 18 frames.



#### Step 7: Remotion Source-Baking and Component Stamping

1. **Asset Sandboxing:** `series-sower-conductor` copies the validated `.wav` speech stems, resolved Foley files, and ambient loops into the local public assets directory of `goblin-viewport-template`.


2. **Template Metaprogram Compiler Invocation:** The conductor invokes `generator/generate-episode-repo.ts` inside `goblin-viewport-template` via child process CLI, providing `dialogue_ast.json`, `exposure_sheet.json`, and staged asset manifests.


3. **Source-Baking the TSX Codebase:** The generator scaffolds an autonomous episode directory inside `goblin-episodes/epXXX/` and source-bakes `Episode_XXX.tsx`:


* Track 1 mounts the speech stems at their quantized frame start positions.


* Track 2 mounts spot Foley transient sequences with literal asset paths inlined as static strings.


* Track 3 mounts continuous ambient loops with the hardcoded -14 dB quadratic ducking volume envelope.


* Presentation primitives are vendored directly into the episode directory.


* *No visual character plates, diffusion mattes, viseme cutouts, or camera motion layers are mounted into the composition tree at this stage*.




4. **Cockpit Stamping Receipt:** The conductor writes static JSX literal confirmation receipts directly into `cns00`.



#### Step 8: Headless Render Execution and Artifact Sealing

1. **Headless CPU Compositing:** `series-sower-conductor` spawns the Remotion CLI against the stamped episode workspace using software-rasterized OpenGL (`--gl=swangle`), concurrency clamped to a single worker (`--concurrency=1`), and off-thread media decoding (`--offthreadvideo`). The render executes purely in system RAM with 0 MB dedicated GPU VRAM, leaving Rig 2 silicon unconstrained.


2. **Acoustic Master Deliverable Emission:** Remotion bakes the multi-track composition into the target container, exporting a synchronized, conformed media artifact containing pristine dialogue, deterministic Foley hits, and ducked ambient audio beds.


3. **Cryptographic Provenance Manifest:** The conductor computes SHA-256 digests of the source `.fountain` screenplay, the compiled AST, the timing manifest, and all conformed audio binary stems, locking them into `render_manifest.json` under C2PA provenance headers.


4. **Sealing to Disk & Cockpit Teardown:** The media artifact, frozen TypeScript composition, vendored assets, and cryptographic manifest are committed into `goblin-episodes`. The conductor emits the final `>> [LIFECYCLE] [OK] Lifecycle completed: SEALED (0 MB VRAM)` banner to `cns00` and unbinds curses listeners cleanly.
